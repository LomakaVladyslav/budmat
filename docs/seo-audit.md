# SEO-аудит БудМат Кагарлик

Дата перевірки: 6 вересня 2026 року. Основний домен: https://budmat-kaharlyk.com.ua.

## Вихідний стан

Перевірка публічного сайту до змін показала:

- Усі **62 URL** початкової карти сайту відповідали HTTP 200. На кожній сторінці були власна канонічна адреса, один H1 та українська/російська мовні альтернативи.
- Перевірені неіснуючі сторінки та товари відповідали HTTP 404 і містили `noindex`. Загального блокування індексації не виявлено.
- Перевірені **62 внутрішні посилання та адреси зображень** головної сторінки відкривалися успішно. Усі 32 зображення мали атрибут `alt`; декоративні зображення — порожній.
- HTML української головної сторінки мав **303 634 байти без стиснення**. Це розмір відповіді HTML, а не всього завантаження сторінки й не оцінка Core Web Vitals.
- Карта сайту ставила дату кожної збірки як дату оновлення всіх сторінок незалежно від змін контенту. Значення `priority` і `changefreq` не впливають на обробку карти сайту Google.
- У JSON-LD головної сторінки повторювалися повні дані Product/Offer для всього каталогу. Google рекомендує розмітку Product для сторінок окремих товарів; для списку доречні посилання ItemList.
- Початковий `npm audit` повідомив про **7 вразливих пакетів: 6 high, 1 critical**. Це оцінка залежностей; експлуатацію кожної вразливості саме в цьому розгортанні не встановлювали. Початкова версія Next.js — 15.1.11.
- На публічному сайті не було заголовків `X-Content-Type-Options`, `X-Frame-Options` та `Referrer-Policy`. HTTPS і HSTS працювали.
- Перенаправлення з `/?utm_source=...` втрачало параметри запиту.

Висновки щодо доступності та коду мають високу впевненість. Фактична кількість сторінок в індексі Google, позиції, пошуковий трафік і показники реальних відвідувачів невідомі без даних Search Console та аналітики.

## Перевірка після змін

Перевірено production-збірку на `http://127.0.0.1:3000`:

| Перевірка                               |       До змін |                   Після змін |
| --------------------------------------- | ------------: | ---------------------------: |
| URL у карті сайту                       |            62 |                           74 |
| Сторінки категорій                      |             0 | 12: 6 категорій двома мовами |
| Вразливі пакети за `npm audit`          |             7 |                            0 |
| Next.js                                 |       15.1.11 |                      15.5.25 |
| HTML української головної без стиснення | 303 634 байти |               291 965 байтів |

Повний HTTP-сценарій пройшов: **74 сторінки карти сайту, 30 локальних зображень, 6 неіснуючих маршрутів, перенаправлення та robots.txt**. Усі перевірені сторінки мають коректні канонічні адреси й мовні альтернативи; нові категорії доступні для індексації. Параметри запиту зберігаються в постійних перенаправленнях незалежно від заголовка мови браузера.

Розмір HTML головної зменшився на **11 669 байтів, або 3,84%**, попри додавання навігації та корисного тексту. Це вимірювання декодованого HTML, а не швидкості завантаження чи Core Web Vitals. Зростання позицій у пошуку цими перевірками не вимірюється.

Спроба отримати початковий мобільний звіт через публічний PageSpeed Insights API завершилася HTTP 429 (`RESOURCE_EXHAUSTED`: ліміт запитів сервісу). Тому оцінки Lighthouse та польові Core Web Vitals у цьому аудиті не наведені; дані не підміняли припущеннями.

Автоматичний сценарій перевіряє готовий сайт через HTTP, тому його слід запускати після складання production-версії:

```sh
npm run build
npm start
```

В іншому терміналі:

```sh
node scripts/check-seo.mjs http://localhost:3000
```

Для перевірки після публікації:

```sh
node scripts/check-seo.mjs https://budmat-kaharlyk.com.ua
```

Перевіряються всі URL карти сайту, дублікати адрес, HTTP-коди, заголовки безпеки, title/description, H1, мова документа, canonical, мовні альтернативи в HTML і XML, відсутність `noindex` на доступних сторінках, читабельність JSON-LD, типи розмітки, внутрішні посилання, локальні зображення, справжні 404, перенаправлення зі збереженням параметрів і robots.txt. Це перевірка реалізації, а не заміна Google Rich Results Test або Search Console.

### Завершальна перевірка

Після останнього виправлення клавіатурної навігації production-збірка повторно успішно завершилася: 80 згенерованих маршрутів разом зі службовими. Перевірки TypeScript та ESLint, вбудовані у збірку, пройшли. У браузері окремо підтверджено утримання Tab/Shift+Tab у діалозі, закривання лише верхнього вкладеного вікна через Escape, повернення фокусу та зняття блокування прокручування. Помилок у консолі під час цього сценарію не було. Повний обхід 74 SEO-сторінок не повторювали: після його успішного завершення SEO-логіка не змінювалася. `git diff --check` пройшов; ціни, дані товарів, техніки та контакти не змінені.

## Що потребує налаштування поза кодом

1. **Виправити www-домен у Vercel.** На момент аудиту `https://www.budmat-kaharlyk.com.ua/uk` відповідав 308 із ціллю `https://budmat.vercel.app/uk`. У Vercel → проєкт → Settings → Domains ціль перенаправлення для `www.budmat-kaharlyk.com.ua` має бути `budmat-kaharlyk.com.ua`. Після цього перевірити шлях і параметри запиту. Це налаштування домену платформи, яке може спрацьовувати до коду сайту.
2. **Підтвердити домен у Google Search Console.** Якщо його вже підтверджено — використати наявний ресурс. Подати `https://budmat-kaharlyk.com.ua/sitemap.xml`, перевірити «Індексування сторінок» та URL Inspection для головної, категорії, товару й послуги. Не подавати неіснуючі адреси та версії з параметрами.
3. **Перевірити Google Business Profile.** Назва, телефони, адреса, місце на карті, години та сайт мають відповідати реальним даним. Заповнити відповідні категорії бізнесу, додати власні актуальні фото складу, матеріалів і техніки. Не створювати дублікати профілю.
4. **Збирати справжні відгуки клієнтів і актуалізувати інформацію.** Відповідати на відгуки, підтримувати правильний графік роботи, зокрема у святкові дні. Google називає відповідність запиту, відстань і відомість основними чинниками локальної видачі; значення мають відгуки та посилання з інших сайтів.
5. **Підтвердити комерційні дані.** Періодично перевіряти ціни, наявність, одиниці продажу, тарифи, фактичну зону доставки й послуг. Оновлення тексту та структурованих даних мають відповідати один одному. Не додавати вигадані рейтинги, сертифікати, характеристики чи обіцянки доставки.
6. **Вимірювати результат.** Зберегти дату публікації та порівнювати кліки, покази, запити й сторінки у Search Console за порівнянні періоди. Окремо перевірити мобільні Core Web Vitals / PageSpeed Insights після публікації. Не трактувати один лабораторний запуск як показник усіх реальних відвідувачів.

Технічні зміни покращують доступність і зрозумілість сайту для пошуку. Конкретна позиція та строк її зміни не гарантуються; повторне сканування та індексація залежать від пошукової системи.
