# БудМат Кагарлик

Сайт будівельних матеріалів і послуг спецтехніки з українською та російською версіями. Каталог, ціни й контакти зберігаються в репозиторії; замовлення погоджуються телефоном.

Стек: Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS, ESLint і Prettier. Точні версії залежностей зафіксовані в `package-lock.json`.

## Локальний запуск

Потрібні Node.js і npm, сумісні з установленою версією Next.js.

```sh
npm ci
npm run dev
```

Відкрийте [localhost:3000](http://localhost:3000). Маршрут `/` постійно перенаправляє на `/uk`, зберігаючи параметри запиту. Російська версія доступна за `/ru`.

## Перевірки перед публікацією

```sh
npm run lint
npm run build
npm run typecheck
npm start
```

`npm start` запускає готову production-збірку. Поки сервер працює, в іншому терміналі запустіть:

```sh
npm run check:seo
```

За замовчуванням перевіряється `http://localhost:3000`. Іншу адресу можна передати аргументом:

```sh
npm run check:seo -- http://localhost:3001
npm run check:seo -- https://budmat-kaharlyk.com.ua
```

Перевірка обходить URL карти сайту та перевіряє відповіді HTTP, метадані, canonical, мовні альтернативи, один H1, мову документа, JSON-LD, внутрішні посилання, зображення, заголовки безпеки, перенаправлення, robots.txt і неіснуючі сторінки. Вона не вимірює позиції в Google або Core Web Vitals і не замінює Rich Results Test чи Search Console.

Додаткові команди:

- `npm audit` — перевірка відомих вразливостей залежностей.
- `npm run format` — форматування всього проєкту; команда змінює файли.

Під час production-збірки `next/font/google` завантажує шрифти Inter і Manrope. Для цього середовищу збірки потрібен доступ до Google Fonts; відвідувачам шрифти віддає сам сайт.

## Маршрути та структура

| Маршрут                             | Сторінка                                                                |
| ----------------------------------- | ----------------------------------------------------------------------- |
| `/{locale}`                         | Головна, каталог матеріалів і спецтехніки                               |
| `/{locale}/categories/{category}`   | Категорія будматеріалів із товарами, цінами та порадами щодо замовлення |
| `/{locale}/products/{productId}`    | Окремий товар                                                           |
| `/{locale}/equipment/{equipmentId}` | Окрема послуга спецтехніки                                              |
| `/{locale}/return-policy`           | Умови замовлення, отримання та повернення                               |
| `/sitemap.xml`                      | Карта доступних сторінок із мовними альтернативами                      |
| `/robots.txt`                       | Правила сканування та адреса карти сайту                                |

`locale` — `uk` або `ru`. Сторінки каталогу генеруються під час збірки. Після зміни даних потрібна нова збірка та публікація.

```text
src/
├── app/
│   ├── [locale]/            # Сторінки двома мовами
│   ├── layout.tsx           # metadataBase, іконки та глобальні стилі
│   ├── robots.ts            # Генерація robots.txt
│   └── sitemap.ts           # Генерація sitemap.xml
├── components/
│   ├── sections/            # Секції сторінок
│   ├── shared/              # Навігація, каталог, пошук, перемикач мови
│   └── ui/                  # Кнопки, діалоги та інші елементи
├── data/                    # Товари, техніка, категорії та контакти
├── lib/
│   ├── i18n/                # Мови та словники
│   ├── repositories/        # Доступ до даних каталогу
│   └── seo.ts               # Домен, абсолютні URL, hreflang, JSON-LD
├── constants/               # Перелік категорій
├── middleware.ts           # Перенаправлення на українську версію
├── types/                   # Типи даних
└── utils/                   # Форматування цін та стилів
public/catalog/              # Зображення товарів і техніки
scripts/check-seo.mjs         # Перевірка готового сайту через HTTP
docs/seo-audit.md             # Результати аудиту та зовнішні налаштування SEO
```

## Товари та категорії

Для додавання товару покладіть зображення в `public/catalog/products/` і додайте об'єкт у `src/data/products.ts`:

```typescript
{
  id: 'unique-product-id',
  category: 'cement',
  name: { uk: 'Назва товару', ru: 'Название товара' },
  price: 200,
  unit: { uk: 'мішок 25 кг', ru: 'мешок 25 кг' },
  description: { uk: 'Опис товару.', ru: 'Описание товара.' },
  applications: { uk: ['Застосування'], ru: ['Применение'] },
  features: { uk: ['Характеристика'], ru: ['Характеристика'] },
  image: '/catalog/products/unique-product-id.jpg',
  status: 'available',
}
```

Приклад містить умовні дані: замініть їх фактичними перед публікацією. `price` — число у гривнях за одиницю, зазначену в `unit`. Однакові дані використовуються у видимих цінах і розмітці товару.

Статуси:

- `available` — товар у наявності.
- `order` — під замовлення; дату й умови потрібно погодити.
- `hidden` — товар виключається з публічного каталогу, статичних маршрутів і карти сайту після нової збірки.

Категорії: `cement`, `sand`, `crushed-stone`, `blocks`, `concrete-rings`, `brick`. Їхній порядок задано в `src/constants/categories.ts`, назви — у словниках, тексти сторінок — у `src/data/categories.ts`. Категорія з видимими товарами автоматично потрапляє до статичних маршрутів і карти сайту. Після зміни асортименту перевірте, чи її опис відповідає фактичним товарам, розмірам і фасуванню.

Для нової категорії оновіть `ProductCategory`, перелік `PRODUCT_CATEGORIES`, обидва словники та `categoryContent`. Ідентифікатори товарів і категорій входять до адрес сторінок: змінюючи вже опублікований ідентифікатор, додайте постійне перенаправлення зі старої адреси.

## Послуги спецтехніки

Редагуйте `src/data/equipment.ts`, зображення зберігайте в `public/catalog/equipment/`.

- `price` — числовий тариф у гривнях; `priceNote` пояснює одиницю оплати, наприклад `за годину` / `за час`.
- Якщо тариф договірний, використовуйте `price: null` і перекладений `priceLabel`. Не ставте нуль замість невідомої ціни.
- `specifications`, `applications` і `minimumHours` мають відображати підтверджені характеристики та умови.
- Доступність техніки погоджується телефоном; розмітка Service не оголошує її безумовно доступною.

Сторінка послуги та її запис у карті сайту створюються під час наступної збірки.

## Контакти, локалізація та SEO

- Контактні телефони, адреса, координати та графік: `src/data/contacts.ts`. Після зміни адреси або графіка також синхронізуйте структуровані дані в головній і детальних сторінках: частина адресних полів та години роботи задані в них явно.
- Назва компанії, метадані головної сторінки, тексти інтерфейсу й умови замовлення: `src/lib/i18n/dictionaries/uk.ts` та `ru.ts`.
- Основний домен і спільні SEO-функції: `src/lib/seo.ts` (`SITE_URL`, `BUSINESS_ID`, `absoluteUrl`, `getLanguageAlternates`, `serializeJsonLd`).
- Метадані конкретних сторінок: їхні функції `generateMetadata`; кореневий `src/app/layout.tsx` задає `metadataBase`.
- Product та Service JSON-LD: відповідні детальні сторінки. Головна містить бізнес і список посилань, категорії — CollectionPage, ItemList і BreadcrumbList.
- Карта сайту та robots.txt генеруються кодом у `src/app/`; не створюйте паралельний `public/robots.txt`.

Не додавайте рейтинги, відгуки, марки, характеристики, наявність чи умови доставки, яких немає в підтверджених даних. Час збірки не є датою зміни всього контенту, тому sitemap не підставляє його як `lastModified`.

Додавання третьої мови потребує змін у типі `Locale`, конфігурації мов, завантажувачі словників, усіх локалізованих даних, текстах сторінок і перевірках `scripts/check-seo.mjs`. Частина шаблонів наразі вибирає між українською та російською; одного нового словника недостатньо.

Детальні результати перевірки, налаштування основного домену, Search Console і Google Business Profile описані в [SEO-аудиті](docs/seo-audit.md).

## Підключення API

Доступ до каталогу зосереджено в `src/lib/repositories/`, але зараз він синхронний. Для переходу на API потрібно також оновити виклики в сторінках, `generateStaticParams`, метаданих і sitemap, визначити кешування та спосіб оновлення статичних сторінок. Заміни імпорту на асинхронний `fetch` недостатньо.
